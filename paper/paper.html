Mazemaker: A Layered Memory Architecture with Empirically Observed Bottleneck Migration Across Retrieval, Formation, and Reranking

Graph-Based Memory Formation, Autonomous Consolidation, and Multi-Channel Retrieval
Single EU Operator
Abstract. We present Mazemaker, a persistent memory system for LLM-based agents that combines graph-based formation, autonomous consolidation, and multi-channel retrieval. The system's layered architecture enables a phenomenon we call bottleneck migration: as one processing stage saturates, the limiting factor shifts to the upstream stage. This is observable through a controlled, reproducible experimental loop.

We demonstrate bottleneck migration across a 100-iteration deterministic benchmark (LongMemEval-oracle: 500 questions, ~25k-memory haystack per question, ±0.5 pp run-to-run noise). Retrieval-only tuning saturated at R@5 = 0.7404 across four structurally distinct configurations. Query-conditioned memory formation broke the ceiling, reaching R@5 = 0.8085. Rerank-feedback enabled by the enriched corpus pushed to 0.8426. Top-K sharpness achieved R@10 = 0.9000. Negative controls confirm the architecture is load-bearing: shuffled-edge ablation drops recall from 1.00 to 0.27, post-consolidation synthesis lifts from 0.00 to 0.43, and cross-session continuity holds at 0.62 vs. 0.06 for raw cosine.

The experimental methodology—deterministic benchmark, versioned corpus snapshot (957 MB, SHA-256-pinned), rollback-capable formation passes, and one-command reproduction—enables independent verification. Every result, failure, and configuration is publicly archived.

1. Introduction

LLM-based agents lack persistent memory. This is not a problem of context length—it is a structural problem: the representation of past information does not evolve between sessions. The dominant approach, retrieval-augmented generation (RAG), treats memory as a static vector index. Systems like MemGPT and GraphRAG add hierarchical management or graph structure, but the core pipeline remains: embed once, retrieve by similarity. The memory does not change unless the corpus is re-indexed.

This paper makes three contributions:

1. A layered memory architecture. Mazemaker separates memory into seven stages: ingestion, fact extraction, embedding, consolidation, synthesis, re-formation, and retrieval. Unlike flat index systems, each stage can be independently optimised and empirically evaluated. The retrieval stage fuses eight channels (semantic, BM25, entity, temporal, salience, graph PPR, ColBERT late-interaction, and Dream-Augmented Embeddings) via Reciprocal Rank Fusion. A background consolidation engine continuously strengthens and prunes graph edges, detects contradictions, and bridges isolated clusters.

2. An experimental methodology for continual-memory evaluation. We define a deterministic benchmark protocol with a versioned corpus snapshot, rollback-capable formation passes, explicit negative controls (every architectural mechanism has a knob that must collapse the corresponding metric when disabled), and one-command reproduction. The corpus (957 MB, SHA-256-pinned) is publicly downloadable.

3. Empirical demonstration of bottleneck migration. Over 100 iterations, the limiting factor moved systematically: retrieval tuning saturated at R@5 = 0.7404, memory formation broke through to 0.8085, reranking on the enriched corpus extended to 0.8426, and top-K sharpness reached R@10 = 0.9000. Each era's optima were suboptimal before the upstream stage had been addressed. We also document failed interventions that regressed performance, and a measurable dilution effect when formation passes over-generate.

2. Architecture

2.1 Design Principle

The architecture is designed to separate memory into stages that can be independently optimised. The retrieval stage does not depend on the formation stage having crystallised every fact; the formation stage does not depend on the current retrieval configuration. This separability is what makes bottleneck migration observable.

2.2 Seven-Stage Pipeline

Ingest → Extract → Embed → Consolidate → Retrieve
               NREM → Supers. → REM → Insight [Consolidation Engine]
Figure 1. Five-stage pipeline. Stages 1–3 are write-side; Stage 4 runs autonomously in a background daemon; Stage 5 is read-side.

Stage 1—Ingestion (Sponge). An asynchronous background thread absorbs every conversational turn. Session boundaries detected automatically. Conflict detection at write time. Zero latency overhead.

Stage 2—Extraction (AFE). Raw conversation distilled into structured facts through four phases: Stage A (entity-relation-entity triples), Stage B (NER + coreference, 70× batch speedup: 88 min → 75 s), Stage C (optional LLM pass for user-state inference), Stage S (~10% synthesis yield). 7,637 atomic facts in production.

Stage 3—Embedding. Three channels: BGE-M3 at 1024 dimensions (primary), ColBERT@1.5 (late-interaction reranker), Dream-Augmented Embeddings (graph-neighbourhood-weighted, 97.7% coverage). Fused via RRF with five auxiliary channels (BM25, entity, temporal, salience, PPR).

Stage 4—Consolidation (Dream Engine). A background daemon on GPU performs continuous maintenance. The consolidation cycle: NREM three-slice sampling strengthens/prunes edges (GPU PPR ~6.6 ms/seed), Supersedes detects conflicts (cos > 0.85, Δt > 24h), REM bridges orphan clusters, Insight runs Louvain community detection. Production: 44,439 sessions, 173M edges strengthened, 19M pruned, 72M bridges.

Stage 5—Retrieval. Eight-channel fusion via RRF (k = 60): semantic, BM25, entity overlap, temporal recency, AFE salience, PPR graph proximity, ColBERT@1.5, and DAE. The lean configuration (semantic + entity + PPR) outperforms full eight-channel by +0.18 R@5 on real prose (n=200).

3. Experimental Methodology

The methodology itself is a contribution: many of these practices are absent from existing memory-system evaluations.

Deterministic Benchmark. 500 questions, ~25k-memory haystack per question (LongMemEval-oracle). Identical corpus + identical config + identical seed produce identical scores to four decimal places. Run-to-run noise: ±0.5 pp at n=500.

Corpus Versioning. Single Postgres snapshot (mm_bench_raw, 957 MB), SHA-256-pinned. pg_restore + one command reproduces the entire 100-iteration trajectory.

Rollback Discipline. Each formation pass is namespaced for atomic rollback via single SQL DELETE. Regressions (6 of 12 passes) are verifiably reversable.

Negative Controls Protocol. Every architectural mechanism has a quantifiable ablation that must collapse the corresponding metric when disabled. Six controls in Section 5.

4. The 100-Iteration Bottleneck Migration

We ran 100 iterations of the deterministic LongMemEval-oracle benchmark, each corresponding to a distinct system state. Four architectural eras emerged—each era's ceiling only became visible after the prior era had saturated.

Figure 2. The 100-iteration trajectory. Four eras are clearly visible: retrieval saturation (iter00–72), formation breakthrough (iter74–81), rerank-feedback (iter83–95), and top-K sharpness (iter96–100).

4.1 Era 1: Retrieval Saturation (iter00–72)

Anchor at R@5 = 0.6851. We spent 72 iterations sweeping the retrieval-side knob surface: channel weights, ColBERT rerank coefficient, DAE coefficient, candidate pool size, temporal decay, salience weighting, multi-recall path, intent boost.

The ceiling. Iter72 produced R@5 = 0.7404. Iterations 67, 68, 69, and 72 are four structurally different stacks (different ColBERT weights, pool sizes, temporal weightings, salience floors). All four land at exactly R@5 = 0.7404 to four decimal places. Not 0.7402 vs 0.7406—the exact same number. The benchmark is deterministic. Four different stacks converging to one number is a ceiling.

4.2 Era 2: Formation Breakthrough (iter74–81)

Method. For each question type at a plateau, identify gold sessions whose memories are not in top-5. Send each session + query to GPT-5-nano: "what user-side facts would answer this future question?" Emit atomic facts, embed, insert with distinct namespace for atomic rollback.

4.5 The Dilution Effect

Each type-targeted formation pass gains 6–22 hits on its type but trades 2–6 hits across others. Two documented examples:

  • Iter82 (KU rebake, rolled back). Added 12 facts, regressed aggregate R@5 by 2 pp. The new facts resembled MS and TR facts, pushing actual gold out of top-5. Atomically reverted.
  • Permissive SSP prompts (−10 pp). Three rounds of less restrictive prompts regressed SSP R@5 by ~10 pp. Redundant rephrasings crowded high-signal originals out. Rolled back; per-session cap of ~6 facts established.

Dilution is only detectable on a deterministic benchmark with rollback capability. On a stochastic benchmark it would be invisible below the noise floor.

4.6 Failed Interventions

  • Naive canonicalization (−3 pp). 176 pre-emitted canonical statements across the corpus. Semantic compression destroyed discriminative identity.
  • Salience over-boost (regression). At weight > 0.5, rebake facts won top-5 on unintended queries. Only observable on a graph engine with non-trivial relevance formula.
  • BGE-reranker-v2-m3 (−8 pp MS). Single-session held; multi-session collapsed. Over-weights surface-form similarity, penalising bridge facts.
  • Keyword-strip multi-recall (regression). Bag-of-keywords rewrite lost the intent signal.

8. Related Work

External memory. Neural Turing Machines and Differentiable Neural Computers introduced differentiable external memory for narrow algorithmic tasks. Complementary Learning Systems theory models consolidation at the biological level. Mazemaker is the first production system operationalising the full CLS paradigm.

RAG variants. RAG, GraphRAG, and HybridRAG add structure to retrieval but treat the index as static. Mazemaker's graph evolves.

LLM memory. MemGPT and MemWalker add hierarchical memory but do not consolidate or evolve the representation. Generative Agents include reflection but lack persistent graph maintenance.

Spreading activation. Collins and Loftus and ACT-R provide the cognitive basis for graph-based associative recall. Mazemaker implements spreading activation at production scale.

9. Limitations

  • No external baseline runs. We have not evaluated strong implementations of GraphRAG, MemGPT/Letta, or comparable systems on the same benchmark.
  • Single dataset. Bottleneck migration demonstrated on LongMemEval-oracle only. Generality unconfirmed.
  • Tier-3 continuity drops. At 6,200 noise memories, continuity drops to 0.20. The absolute lift narrows.
  • Limited statistical power. 500-question benchmark has ±0.5 pp noise; per-type breakdowns (SSP: n=30) have wider variance.

10. Conclusion

The central empirical finding: a layered memory architecture with separable stages exhibits bottleneck migration. The limiting factor moves systematically from retrieval to formation to reranking as each stage is optimised. This migration is observable, reproducible, and attributable to specific stages.

Implications are practical: if retrieval-side tuning plateaus, the bottleneck may not be retrieval at all—it may be upstream, in how memories are formed. If formation is optimised, the retrieval-side knobs may need recalibration because corpus density has changed. And every formation intervention carries a measurable dilution risk, only detectable on a deterministic benchmark with rollback capability.

These findings do not depend on Mazemaker's specific implementation. Any persistent memory system with distinguishable write-side and read-side stages is subject to the same dynamics. We hope the experimental methodology—deterministic benchmark, versioned corpus, negative controls, rollback discipline, public artifacts—provides a template for evaluating future systems.

Memory is not retrieval. Memory is formation.
